## 🎯 How It Works

Three Supabase tables, one API:

```
Configuration
    ↓
NEW     → documents table        (data_oss)
OLD     → documents_old table    (scraped_dpmptsp)  
COMBINED→ documents_combined table (both)
    ↓
rag_api_datasets.py
    ↓
?dataset=NEW|OLD|COMBINED (query parameter switches datasets)
```

## 🚀 5-Step Quick Start

```bash
# 1. Verify system
python verify_multi_dataset_system.py

# 2. Ingest datasets (first time only)
python ingest_supabase_datasets.py --dataset OLD
python ingest_supabase_datasets.py --dataset COMBINED

# 3. Start API (Terminal 1)
python rag_api_datasets.py

# 4. Run tests (Terminal 2)
python run_retrieval_test_datasets.py --dataset NEW --limit 50
python run_retrieval_test_datasets.py --dataset OLD --limit 50
python run_retrieval_test_datasets.py --dataset COMBINED --limit 50

# 5. Analyze results
python analyze_retrieval_test_datasets.py
```

## 🔌 API Endpoint Examples

### List all datasets
```bash
curl http://localhost:8001/datasets
```

### Retrieve from OLD dataset
```bash
curl -X POST http://localhost:8001/retrieve?dataset=OLD \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "question"}]}'
```

### Chat with COMBINED dataset
```bash
curl -X POST http://localhost:8001/chat?dataset=COMBINED \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "question"}]}'
```

## 📈 CSV Output (One Per Test)

Each test generates a CSV with:
- Query ID, question, category
- Retrieved chunk IDs
- Ground truth chunks
- Search method (vector_only, enhanced_vector, internet_fallback)
- Retrieval time (seconds)
- Precision, Recall, F1 Score
- Notes

Files saved to: evaluation/retrieval_test_result_[DATASET]_[TIMESTAMP].csv
